# 客户管理系统

## 这版的用途

导航栏「客户管理系统」默认展示员工负责的发送活动，按员工、发送时分组、发送活动和客户明细逐层查看。使用现有联系人、EDM 活动、站内信任务和收件箱；发送任务自动记录实际内容，不增加客户发送步骤或 AI 调用。

主路径为 **员工活动 → 客户分组 → 发送活动 → 效果与客户名单 → 客户档案**。员工层展示联系人数、分组、活动数和最近发送；分组层展示员工联系这一组的情况；活动层展示主题、渠道、首次及最近发送时间；活动详情点击已发送、已打开、已点击、已回复、失败或待核实指标，即可筛选这一员工、这一分组、这一活动对应的分页客户名单。打开、点击、回复可以重叠，不能按互斥状态判断。返回、刷新和浏览器后退保留层级与筛选。

客户资料、全部沟通记录和客户回复保留为辅助入口。名单可搜索、分组及管理导入；沟通记录可下载全部筛选结果；回复复用原收件箱的分类、负责人、处理状态及收信设置。

“发送活动”沿用现有 EDM 活动或站内信任务 ID。同一活动追加发送累计展示，不冒充一次启动发送的独立轮次。员工归属为活动负责人，不将负责人说成实际点击发送的人员。今后的发送在实际内容快照中自动保存当时分组，客户移动分组或分组改名不会改写这些记录；没有历史快照的发送归入“历史分组未记录”，明确没有分组的记录与历史缺失分开。客户资料页仍显示当前分组。

EDM 打开与点击使用已有客户级事件，展示追踪覆盖范围；缺少追踪不能显示为已确认零次。供应商仅提供活动整体报告时，不能把总量分配给分组或编造客户名单。站内信无打开/点击指标，展示提交结果、待核实及确认回复。打开记录表示像素加载，点击记录表示链接访问；记录时间是系统收到数据的时间。

客户详情按时间展示发送与回复，以及业务人员记录的跟进。网站目标保持准确网址身份；网站与联系人合并需要明确人工关联，不根据公司名或域名自动猜测。站内信填写的发件邮箱属于业务人员，不能作为客户邮箱。

## 记录与权限

新发送保存每个目标的实际个性化内容及供应商结果。旧记录缺少原内容时明确显示未保存，不用当前模板伪造历史邮件。失败、待核实、未追踪、自动回执、退信及已确认人工回复分别显示。

权限沿用现有工作区与角色。成员看本人或获分配的沟通；管理员与数据主管按已有团队权限看汇总；正文访问继续遵守收件箱的限制。只读角色不能修改跟进和关联。

从客户详情「写邮件给客户」进入现有发送邮件流程，预选一个准确联系人，草稿按工作区、员工和客户独立保存。必须正常准备内容、预览、确认后才会发送。不会带入其他批量发送草稿，也不会自动发信。

## 接收客户回复

客户回复需要管理员配置收信域名、转发邮箱和既有接收 Worker，并完成实际来信与转发验证后启用。未接通时显示配置状态与未追踪，不能当作零回复。外部 Gmail 或 Outlook 手工发送的邮件没有授权邮箱同步时不会自动进入系统。

本次实现不更换现有 DNS/MX，不伪造真实来信验收。接收链路沿用 [客户收件箱](customer-inbox.md)。

## 实施与验证顺序

1. 为不可变发送内容、人工关联和跟进补充必要表与索引，不复制现有客户库。
2. 完成工作区/角色隔离的分页查询、客户时间线、员工统计、记录下载。
3. 在发送队列保存实际内容与结果，保留原幂等和待核实保护。
4. 完成员工、分组、活动和客户逐层视图，复用联系人导入、收件箱及客户档案，保留单客户邮件草稿。
5. 验证多员工同客户、跨活动与渠道、20,000 条分页/导出、历史缺失内容、重复回调、只读/跨工作区权限，以及桌面和手机页面。
6. 隔离构建与发布，应用新增数据库迁移，保持原绑定及变量，核验线上版本、资源与健康。
