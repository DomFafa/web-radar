# 产品资料到原生模板

Product Radar 保管产品事实、原图、资料快照和生成任务；Web Radar 发布可执行的模板合同，并把确认后的资料放入对应版本的原生页面。新增产品不需要产品名称分支，新增使用同类能力的模板不需要再修改 Product Radar。

## 新版 Pawfect 合同

`2026-10-02.pawfect-groom-materials.2` 将已认可的页面结构变成生产渲染规则。主图继续用于目录和详情；首页首屏、图文区、画廊、介绍页和联系页使用按产品 ID 绑定的新场景。首页精选最多 6 个产品，画廊最多 3 个产品；目录保留全部选定产品。历史合同及其项目继续使用原版本。

合同新增两项明确声明的能力：

| 能力 | Product Radar 的执行行为 |
| --- | --- |
| `website.visual-plan.v1` | 在同一次规划中读取带产品 ID 的主图和事实，规划全站共同的摄影方向、各位置的构图和容量内文案；生成每张图片时再次传递该图片所绑定产品的事实。 |
| `image.generate-new.v1` | 支持图片槽的 `reusePolicy: generate-new`；不采用旧场景，不合并不同槽的生成任务，确认和接收时检查图片内容哈希。 |

缺失或冲突的规格仍然是缺失或冲突；提案规格仍保留提案状态。图片、模板示例和营销文案不能补造材质、尺寸、证书、工厂、销量或承诺。

`websitePalette` 是模板声明的默认网页色板。新版 Pawfect 保留暖白、青绿和琥珀的视觉基线，规划结果采用同一色板；用户随后主动修改品牌色的既有能力保留。环境可与网站协调，产品本身的颜色、标识和材质始终服从原图与产品事实。

## 模板要求如何编写

每个图片槽必须描述页面上的真实用途，并明确 `materialSource`、`productScope`、`repeat`、尺寸、比例、桌面/手机安全区域和复用策略。用途应写成“展示所绑定产品的自然使用场景”，避免把示例产品、行业或场所写成通用要求。

- `product-primary` 必须复用客户选定主图；模板的目标尺寸不能成为重画或裁切产品的授权。
- `slot-image` 配合 `scene` 和 `product-reference` 时，明确绑定一个真实产品；该产品的主图是生成参考。
- `generate-new` 只用于生成槽，须声明对应能力。多个新场景采用共同摄影方向，但各自具有不同作用和构图。
- `per-selection` 用于数量有限的展示区，选择数由合同决定；目录和详情按所有产品生成，不能为了首页容量漏掉产品。
- 只有确有业务 brief 的业务插画才使用 `illustration`；模板示例中的人、动物、工厂或团队不能代替客户资料。

文字槽对应渲染器实际消费的标题、说明、卡片、问题或答案。每项声明 `maxCodePoints`、`maxLines`、`factSources` 和事实要求。标题重点、行距、色彩、图框、留白和响应式行为由 HTML/CSS 决定，模型只填写纯文本。不要让模型输出整块 HTML，也不要登记页面不会使用的文案。

新的槽位语义或布局必须发布新 `contractRevision` / `rendererRevision`，并提供准确的目录摘要、示例资料和新版渲染截图。不能原地改写旧版本，也不能把旧模板截图标成新合同。

## 验证与线上使用

开发验证覆盖 1、3、7 个产品的规划、确认资料包、接收校验和原生渲染，并保留旧合同哈希及渲染检查。桌面和手机检查图片完整性、文字容量、产品链接、菜单、FAQ 和询盘入口。模型调用被模拟的测试只证明程序和合同，不证明生成图质量。

上线后刷新模板目录，核对新合同，再创建新的资料草稿。规划到 `awaiting_generation` 后，按现有流程确认生成；待素材完成后确认并提交，打开接收端实际预览。旧资料不会自动换合同，原公开网站不会自动重发。

视觉验收使用真实、品类不同的产品资料和生产生成服务，记录产品 ID、合同、任务及网站版本、主图哈希、新图角色与生成状态、桌面和手机结果。保存和交接成功、程序回归通过、视觉验收通过和部署完成分别记录。
