# Static showcase generation

Approved in the conversation: preserve the Web Radar UI, replace the video creation step with five website page designs generated by Image 2.5, and use the supplied screenshot-to-code backend to produce real static HTML.

Flow: company and products → style → copy → generate homepage → confirm homepage → generate catalog, detail, about and contact using the confirmed homepage → confirm all five → build → private responsive preview → publish. Each design supports instructions and regeneration. Product detail is a template expanded for each product. English and the existing optional second language remain supported.

The five steps retain the current visual shell. Existing auth, quota ownership, imported products and published snapshots remain intact. New static sites need no video. Changed content invalidates design approval and built output. Generated assets and build results cannot overwrite newer edits or be forged through draft updates.

The Python service runs independently and reuses the provided library's Agent. It has authenticated, persistent, idempotent jobs. It returns self-contained HTML/CSS with actual company/product content and original asset references. No video, external script/CDN dependency, fabricated product specifications or flattened full-page screenshot. Private preview and public deployment use the same immutable artifact. The current Pages publisher remains responsible for deployment.

Local verification is authorized. Production hosting for the Python service remains to be specified; do not describe local tests as production acceptance.
