# Web Radar v1 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for isolated implementation and independent review. Checkboxes track the deliverables; the approved spec takes precedence.

**Goal:** Deliver all approved Web Radar v1 capabilities locally, with explicit real-service dependencies.
**Architecture:** React/Vite shared editor and Hono Worker. D1 stores auth/handoffs and durable business records; a singleton SQLite Durable Object serializes quota reservations and the globally single Agnes queue with alarms. R2 holds private immutable assets. Trusted templates generate Pages artifacts; a fail-closed gateway covers release activation and all deployment aliases.
**Tech Stack:** TypeScript, React, Vite, Hono, D1, R2, SQLite Durable Objects, Vitest, Playwright.
**Spec:** docs/web-radar-v1-final-review.md and docs/web-radar-integration-contract.md.

## Global Constraints

- One 8/12 second Agnes task; at least 3/4 confirmed reference images; no FFmpeg/Containers.
- New dedicated keys only. No PR secrets read/copied. Test provider requires explicit test environment and labels; production fails closed without configuration.
- Creator/current workspace admin/platform admin authorization, revalidated via PR. Same draft across standalone and embed; optimistic version conflicts.
- Initiator quota reserved atomically, consumed only after saved delivery, released on technical failure. Unknown video submissions retain their reservation and global slot.
- Draft/private media inaccessible without current authorization. Publishing changes immutable release only on success; restore preserves draft, quota, inquiries.
- No real email, external customer publication, subscription purchase, or deployment in this implementation session.
- Work only in this repository on codex/web-radar-v1. User approved complete v1; do not repeat approval.

## Interfaces and file ownership

`src/shared/model.ts` is the shared data model. `docs/web-radar-internal-api.md` defines client routes. Root owns scaffold, auth/integration, Worker routing and joint QA. Domain implementer owns `src/worker/domain*`, `src/worker/coordinator*`, business migrations and tests. Frontend implementer owns `src/client/*`. Media/site implementer owns `src/worker/providers/*`, `src/templates/*` and their tests. No cross-owner file edits without coordination.
