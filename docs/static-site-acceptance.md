# 静态展示站改造验收

日期：2026-09-13。当前工作区保留了原有未提交修改。本次没有提交、推送或生产部署。

## 实现范围

保留 Web Radar 的工作台样式和五步导航，将新网站的视频步骤改为页面设计稿：资料与产品 → 网站风格 → 网站文案 → 首页设计并确认 → 其余四页设计并确认 → screenshot-to-code 构建 → 预览与发布。详情设计自动扩展到每个产品，继续支持英语和一种第二语言。

公司资料、产品、语言、文案或设计方向变化会使旧确认和构建失效。草稿更新不能伪造服务端设计状态；旧任务不能覆盖新输入。公开页面使用原始产品素材，设计图保持私有；原有已发布快照继续保留。

Python 服务通过认证接口导入 `screenshot-to-code-main/backend` 的 Agent，源码未修改。任务和结果持久化在 SQLite，重复查询不重新调用模型。HTML 清理后绑定真实资料、图片、页面导航和可信询盘表单；Worker 在标记构建成功前检查页面齐全、资产归属及发布后文件大小。

## 真实模型验收

使用既有 senseng 项目资料及五个产品，在隔离测试中调用真实 Image 2.5，成功生成首页、产品、详情、关于和联系五张设计图。内页生成以前述首页为首张参考图，并使用原始产品图。

真实 screenshot-to-code 首轮成功生成 9 个英语网页：4 个通用页面和 5 个产品详情。浏览器验证 18 个页面/视口组合，所有原图加载、导航和本地拦截的询盘提交通过；没有真实发送询盘或修改生产项目。视觉检查另外发现长文案挤压导航、详情网格错位和重复导航，因此首轮不作为最终视觉验收。

针对首轮视觉证据，转码上下文现在提供最终文案的最长长度及页面标题绑定，明确导航唯一、详情图文同排、原图完整显示且单图产品不创建假缩略图。导航组装会归一化嵌套占位符并去重；CSS 允许空字符串伪元素用于装饰，仍移除非空模型文案。四项新增回归和独立复核通过。

第二轮又发现两类不同原因：组装器为图像链接补标签时误删图片子树（已以三个失败回归复现并修复）；模型用 CSS 画产品、遮挡真实原图，部分导航仍竖排。第二轮没有作为最终视觉验收。新增独立可见性检查在此产物上正确失败，避免“图片下载成功”被误当成“图片实际可见”。

为解决这组实际问题，构建增加了清理后的代表页渲染检查；只向服务发送主产品原图及可选 logo，连同五张设计图共用原始 45 MiB 上限。失败页面基于原 HTML、原设计及实际渲染反馈最多修正一次；通过页面不重做。

第三轮真实任务 `7f218509-f790-4258-bb02-019008b22d23` 于 19:38 完成，仍使用原五张设计图，输出 9 个英语网页。18 个页面/视口组合的图片下载、页面跳转和本地拦截询盘提交通过，无脚本异常。此结果是功能联通证据，**第三轮整体视觉验收未通过**：产品页的长副标题被模型放进品牌栏，挤压导航；关于页装饰产生 2px 横向溢出，手机端产品图部分被覆盖；联系页仍用 CSS 形状模拟产品。

第三轮后停止整站付费重试。导航问题按实际父容器及长品牌副标题修正组装规则；图片遮挡比例、导航容器边界与溢出检测对齐完整浏览器验收。提示词明确禁止任何页面用 CSS 绘制产品或包装。提示词变化尚未进行第四轮真实生成，不能据此声称视觉质量已经解决。导航修正规则已直接应用于同一份第三轮 HTML，未重新调用模型；只有产品页和关于页发生组装变化，桌面/手机导航均恢复正常。修正后的 18 项功能检查再次通过，关于页溢出/遮挡和联系页 CSS 产品问题仍保留为未通过项。既有第三轮产物不会冒充最终通过版本。

真实调用与截图证据位于 `artifacts/static-site/real-canary/`；前两轮保留在 `attempt-1/`、`attempt-2/`，第三轮原件保留在 `attempt-3-original/`。`assembly-correction.json` 记录零模型调用的导航修正；`functional-result.json` 明确记录功能成功、视觉未通过及具体问题；`layout-diagnostics.json` 保留真实布局几何信息。五张设计图无需因代码还原修正重新生成。

最后用收紧后的渲染门禁直接复测同一真实产物：产品页通过，关于页正确拒绝桌面/手机溢出及手机 6/9 图片可见点（要求至少 7/9），见 `final-gate-result.json`。没有为该验证发起新的模型调用。本文记录的本地预览可用于审阅，尚不是视觉验收合格的交付版本。

## 运行与线上状态

`npm run dev:builder` 在 `127.0.0.1:7002` 启动独立服务，复用私有 `.dev.vars` 中已有文字 API 配置。`SITE_BUILDER_KEY` 已本地配置，`SITE_BUILDER_URL` 保持空值，避免将不可访问的本机地址用于生产。密钥不出现在仓库或验收记录中。

生产转码服务需要一个可由 Worker 访问的 HTTPS 地址、单实例 Python 进程、持久化 SQLite 存储和 Playwright Chromium。供应库执行未清理 HTML 的截图工具继续关闭；新增的独立渲染检查只接收清理并绑定后的网页，禁用脚本并阻断网络。现有线上 Web Radar 尚未切换到新流程。上线前还需要完成真实内页视觉验收，并落实上述服务地址与运行环境。
