# 平台稳定性与性能优化（2026-09-17）

## 本次交付

- 新生成的以图生站 HTML 写入私有 R2，以内容 SHA-256 命名。D1 只保存引用、文件数、字节数与摘要；读取时检查项目归属、长度和摘要。旧版内联 HTML 继续可读，保存或发布时转换。普通草稿保存不能伪造生成结果、任务状态或 R2 引用。
- 项目列表改为摘要 API：默认每页 20 个，最大 100 个，按更新时间、创建时间、ID 倒序；筛选、搜索、总数及权限过滤均在服务端执行。列表不再返回草稿、生成 HTML 或任务快照。
- 项目详情默认最近 20 条任务和发布记录，额外保留未结束任务和当前发布版本。历史发布不返回草稿副本，任务不返回生成输入快照。`GET /api/projects/:id/history?kind=jobs|releases&page=1` 提供每页 20 条历史，界面可分页查看。
- 生成、发布、邮件和其他任务分为独立执行通道；上游网络调用可并行，任务领取、额度结算和数据库状态变更仍受短串行锁保护。视频全局占用保护保持有效。上传文件的传输不再持有全局写锁，注册素材前重新检查项目是否存在。
- 已完成、失败、暂停、停止、待核实任务均停止自动轮询。以图生站同步失败采用退避，连续 6 次失败后停止，支持手动同步；隐藏标签页降低请求频率。
- Logo、favicon、产品图和设计图使用真实上传字节进度、估算剩余传输时间及取消。100% 传输后单独显示服务器保存阶段；取消/失败不自动重传或重复提交，已经成功上传的图片保留。
- 预览支持产品搜索和表单填写/校验，仅显示本地模拟提交结果，不发送询盘。
- 新增 favicon 上传，PNG/JPEG/WebP/GIF/ICO 文件检查；选用的图标进入模板、生成页面、预览与发布输出。
- 所有生成 HTML 经 DOM 解析清理脚本、事件属性、危险 URL、嵌入内容和 SVG 动画，再注入应用维护的询盘/搜索脚本。生产管理域名的公开页面入口重定向到独立站点域名，防止生成页面获得管理后台的同源权限。
- 参考网页抓取校验 DNS、公网地址和每一次跳转，仅接收 HTML，限制大小为 1 MB、最多 3 次跳转、请求时长。DNS 校验与 HTTP 连接不是地址绑定；独立服务器仍应在出站网络层拒绝私网地址，不能把应用校验视为完全阻断 DNS 重绑定。
- 管理员备份导出新增 R2 对象清单，覆盖上传素材、当前和历史生成文件，以及可选的运行中克隆检查点。`scripts/verify-backup.mjs` 可离线验证文件完整性及生成产物摘要。
- 生成后通过 Python 服务抽查首个语言的首页、产品列表、关于、联系与主产品详情，在 390/1440/2560px 下检查溢出、坏图和正文，保存私有截图报告。检查问题或已配置服务暂不可用时保留页面、暂停自动发布。未配置服务时显示明确提示，不伪造检查通过。结构检查和缩略图色差不等于视觉还原验收；本次不追加付费模型修复调用。
- 智能模式在抽样检查提示首页过短时，最多进行一次本地补充：只引用已有产品、图片及联系信息，沿用品牌色，再重新检查。不改动忠实还原模式；填写定制指令时优先交给模型执行，不叠加固定模块。不产生额外模型费用。
- 发布时添加 canonical、Open Graph、多语言 alternate、sitemap.xml 和 robots.txt。静态站点 HTML 使用 private/no-cache 允许条件请求减少重复正文传输，每次仍验证发布开关；错误和询盘保持 no-store。
- 平台管理员可查看近 30 天任务数量、状态和耗时，接口另含供应商尝试结果计数；不推算未知模型费用。
- CI 增加无外部模型调用的 Chromium 回归，覆盖刷新恢复、暂停、继续、停止、发布去重及完成后停止请求。

## 发布顺序

1. 备份 D1，并从管理员导出获取业务数据和 R2 对象清单，复制清单中的必需对象。原始 D1 备份包含敏感业务和会话数据，应保存在受限目录。
2. 先更新 Python site-builder 服务，安装 Chromium，确认受相同 Bearer 密钥保护的 `/v1/clone-quality` 可用，再更新 Worker。质量渲染单独限制一个并发，最多 90 秒，不会调用模型。
3. 执行 `npx wrangler d1 migrations apply web-radar --remote` 应用 `0005_project_summary_indexes.sql`。该迁移仅新增查询索引。
4. 执行 `npm ci`、`npm run check`、`npm run test:browser`，然后按既有流程构建、部署 Worker。
5. 新前后端应一起发布：项目列表 API 已改为摘要分页，不再提供 `project.draft`。
6. 验证新建/旧站点预览、发布和历史版本恢复。旧的已经部署到 Pages 的 HTML 不会自动重写；重新发布后才应用本次 HTML 清理。

回滚应用时保留 R2 产物和索引。已经转换为 `cloneConfig.artifact` 的项目需要支持该引用的 Worker；不能直接退回只读内联 HTML 的旧版本。若必须完整回滚，应恢复配套 D1 快照，并保留所有被旧发布引用的 R2 对象。

## 备份恢复演练

将 R2 对象按原始 key 保存到安全目录，保留导出的 JSON：

```sh
node scripts/verify-backup.mjs /secure/export.json /secure/r2-copy
```

验证命令仅检查文件，不上传、不覆盖数据库。恢复演练应在隔离 D1/R2 和测试域名执行：先恢复对象，再恢复同一批数据库快照，核对项目/发布数、预览图片、产物摘要与站点访问。当前/历史发布引用的对象和暂停任务检查点都不得按年龄直接删除。正式数据的定时备份、保留周期和自动清理尚未启用。

## 后续需要独立验收的事项

本次仍不保证任意设计图的像素级还原。自动视觉修复属于额外模型调用，应结合实测成本和质量阈值再启用；独立服务拆分、真实业务容量压测和生产定时备份也需要按实际规模安排。当前渲染检查不会替代人工视觉验收，下线校验仍在每次站点请求前执行。
