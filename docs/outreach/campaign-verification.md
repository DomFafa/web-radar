# 邮件发送结果核实

“待核实”表示发送请求已经尝试，但没有可信回执。它不是送达、打开、点击的等待状态。

## 手动核实

在发送记录的任务详情中点击「立即核实」。后台任务分页读取原 Resend 帐号，按冻结的发件人、收件人和 `wr_recipient_id` 标识确认邮件；已有服务商 ID 时直接读取该邮件。关闭页面不会终止核实，重新打开可查看查询进度、确认数和剩余数。

- 仅有相同邮箱不足以匹配；无标识、多个匹配、权限不足或查询失败时保持待核实。
- 查询不会发送邮件、重新入队收件人、清除发送尝试或恢复暂停任务。
- 限流后延迟继续；失败或长时间无进展可重新发起。
- 当前远端查证支持 Resend。缺少冻结快照或使用其它服务商时明确提示人工核实。
- 新收到的可信 Resend 回调也会更新任务；全部不确定结果消除且无待发邮件后，自动退出待核实。

旧队列仅在不确定发送后延迟恢复尝试（通常约 3 分钟），没有无限周期核查。无可信证据时不会经过某个固定时间自动判成功。

## 统计口径

本项目已受理按收件人/服务商邮件 ID 去重。Resend Metrics 是帐号级聚合指标，可包含其它域名、其它应用和历史任务；不能将 Metrics 的 sent 直接写入某一活动的 total_sent。

当前本项目送达、打开、点击计数是累计证据：点击可推断打开/送达，后续退信不会抹去曾有的互动时间。比例以已受理数为分母。Resend 的打开/点击率以 delivered 为分母，delivery_rate 以 sent 为分母。时间范围、指标定义、异步事件和缓存都会造成差异。对账应先匹配相同帐号和邮件 ID，再比较原始事件。
