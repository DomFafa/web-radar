## 核实结果

- 线上同一项目包含 10 个产品、英文站点、1 条已回答需求。09:10 的方案校验失败任务已尝试 3 次；09:14 的新任务收到文字上游 HTTP 403。
- 使用本项目 `.dev.vars` 中的 Cloudflare 凭据可以只读查询这三条任务；默认 Wrangler 凭据的权限错误与文字模型的 403 是两个不同问题。
- 用原失败任务的冻结输入和原图重新请求文字模型，返回 HTTP 200，耗时约 37 秒，正常结束。响应包含五个基础页和“包装展示”页，10 个产品译文齐全。
- 该响应在原实现中失败的唯一校验位置为 `pages[5].id`：模型给出 `packaging`，程序的附加页编号要求 `extra-` 前缀。
- 本次没有复现 HTTP 403；历史代码未保存上游错误正文，因此不能把其具体原因确定为欠费、密钥失效或地区限制。本地模型读取成功也不能替代生产 Worker 的请求验证。

## 修改

- `src/worker/providers/consultation.ts`：仅在模型适配层给合法附加页 slug 补充 `extra-` 前缀。仍执行完整方案校验；非法路径、重复编号、缺少基础页、缺少语言或产品译文继续失败。错误提示保留具体字段或语义原因，不显示整份模型响应。
- `src/worker/providers/http.ts`：保留上游错误码、参数、脱敏原因和请求编号。错误正文最多读取 16 KiB；正文损坏、超限或非 JSON 时，仍保留原 HTTP 错误类别。凭据和带签名的 URL 被脱敏。状态不确定判断、技术重试次数与 Retry-After 语义保持不变。
- 没有修改模型、密钥、用户资料、数据库格式、页面权限或任务恢复接口。
