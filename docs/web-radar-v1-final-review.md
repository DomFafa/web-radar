# Web Radar 首版最终搭建方案

日期：2026-09-12。用户已在最终确认入口选择 A，批准本方案的完整首版及标注的建议默认值，进入实施。本文描述目标行为，不代表已经上线；真实配置与验收仍须完成。所有旧选项以本方案及最新确认记录为准。

**首版目标：客户从 Product Radar 勾选产品，或直接登录 Web Radar，完成资料、视频和网站制作，预览确认后发布一个带动态视频 Hero 的外贸公司展示网站。**

## 1. 客户使用流程（已确认）

1. **进入建站。** Product Radar 的已生成产品列表增加建站入口，勾选产品后进入其内部完整建站页面；也能直接登录 Web Radar，上传产品图片、填写资料或选择有权限的 Product Radar 产品。首版向现有 Product Radar 客户开放，沿用现有账号；从已登录的 Product Radar 进入时无需再次登录。
2. **选择产品和市场。** 每站最多 20 个产品，主产品包含在内；选择玩具、电子、户外、厨房、通用等类目和销售国家。英文为基础，可选德语、法语、西班牙语、葡萄牙语、意大利语中的一种作为第二语言，最多两种。
3. **填写公司资料。** 公司名称、联系邮箱、联系人英文名必填；Facebook、Instagram、X 选填；选择贸易商或工厂方向。产品事实与联系方式由客户提供或确认。
4. **选择模板。** 首版做 3 套原创模板，风格为温暖自然、现代科技、户外探索。风格建议不限制产品类目。模板在生成脚本前选好，方便脚本适配网站风格。
5. **准备 Hero 视频。** 客户可以上传已有视频；选择 AI 制作时，按下面的确认流程进行。
6. **生成网站并预览。** 将公司资料、产品、语言、文案和选定视频填入模板。可改文字、图片、视频、联系资料、产品排序及品牌色，保留模板布局。
7. **客户点击发布。** 发布到 Cloudflare 默认地址，后续更新沿用原网址。网站接收询盘，后台保存记录，同时将完整询盘发到该客户填写的联系邮箱。

两个入口编辑的是同一份 Web Radar 项目草稿，不产生两份各自更新的数据。导入的 Product Radar 产品保存为独立快照；之后客户主动检查来源更新、查看差异并选择应用，网站的修改不写回产品库，也不自动覆盖已发布网站。

## 2. 视频与分镜（已确认）

**主产品与方向 → 生成脚本 → 客户确认脚本 → 生成分镜图 → 客户确认整组分镜 → Agnes 一次生成完整视频 → 预览并选用。**

- 总时长首版提供 8 秒、12 秒；按之前的要求，8 秒至少 3 张分镜图，12 秒 4 张。分镜内容、顺序和节奏按具体脚本和产品需求安排，不固定每四秒切换，也不锁定每张图的出现秒数。
- 单张分镜不满意，可以填写修改要求，只重新生成这一张。修改影响视频输入后，需重新确认当前整组分镜。
- 图片使用 Product Radar 同款 Image 2.5，由你提供 Web Radar 专用新 key。客户无需填写任何 AI key。
- 视频使用你指定的 Agnes API，整组已确认分镜作为参考，一次提交完整视频任务。按你提供的限制，全平台同一视频服务账号最多一个任务在生成，其余排队。
- 保存上游任务编号和结果。关闭页面或后台重启后继续原任务；网络超时先查状态，避免重复提交、重复扣额度。
- 3 套模板都有大幅、静音、自动循环的视频 Hero，标题与按钮覆盖在视频上。海报图用于加载或浏览器无障碍回退；正常发布需要可用的视频。

已有视频上传路径跳过 AI 脚本、分镜生成步骤。视频外观仍要检查产品一致性、画面变化与循环衔接，不能用 API 返回成功代替画面验收。先前讨论过的分段拼接、FFmpeg 和付费 Containers 不列入首版。

## 3. 网站内容与模板

**已确认：** 外贸 B2B 展示网站，包含公司介绍、产品目录、产品详情和联系询盘；保留模板布局，支持基础内容编辑。首版没有购物车和零售支付。

**建议采用的具体页面与内容默认值：**

- 首页、产品目录、独立产品详情、公司介绍、联系页面；同一套栏目在 3 套模板内使用不同视觉设计。
- 建站后台先以中文为主，Product Radar 内的入口与提示沿用现有中英文体验；生成的网站使用客户选定的网站语言。
- Logo 和品牌素材可选；没有 Logo 时用公司名称展示，不额外强制上传。没有公司实拍资料时，不虚构工厂照片或把生成场景冒充真实设施。
- AI 依据已提供资料生成可编辑文案和译文；不会补造认证、规模、产能、成立年限或客户名单。缺失的事实省略，或提示客户补充。
- 复用同一条已确认 Hero 视频，用不同语言的网页标题、按钮和正文展示；不自动为每种语言再生成一条视频。
- 发布前展示整站预览供客户检查内容、语言、联系方式和视频；保存草稿可以暂缺素材，发布时明确提示缺少项。

## 4. 账号、权限与额度（已确认）

| 事项 | 首版规则 |
| --- | --- |
| 项目权限 | 创建者和所属公司工作区管理员可以管理网站及询盘；其他普通成员不能访问该项目的草稿、私有素材与询盘。你保留平台管理员权限。 |
| 公司归属 | 以现有 Product Radar 工作区成员关系为准，不能靠填写同一个公司名称获得权限。 |
| 测试期收费 | 暂不额外向现有客户收 Web Radar 使用费，不接在线支付或订阅。 |
| 额度分配 | 你给每个登录账号分别分配图片、视频额度；数量由后台填写。 |
| 谁的额度 | 谁发起新的生成，就使用谁的额度。管理员替别人项目发起生成，用管理员自己的额度。 |
| 计数 | 一张生成图片计 1；一条完整 8 秒或 12 秒视频计 1。 |
| 失败与重做 | 开始时占用额度，结果成功保存并可交付后扣除；技术失败退回。拿到结果但不满意而重新生成，再计一次。 |
| 任务恢复 | 查询、重传、刷新、恢复同一任务不重复扣除，也不改变原来的额度归属。 |
| 不扣生成额度的操作 | 上传已有素材、编辑文字或脚本、查看已有结果、确认和发布。 |

额度跨两个入口和该账号有权操作的网站累计，不自动扣 Product Radar 原有余额，不自动周期重置或赠送未设定的额度。客户使用次数与平台实际 API 成本分开记录。

## 5. 预览、发布与询盘（已确认）

- **预览：** 仅有项目权限的登录用户可查看，覆盖预览页面及其素材。首版没有外部分享链接或预览邀请。
- **发布：** 客户点击发布才更新公开内容；编辑草稿不影响线上版本。发布失败保留上一成功版本。
- **恢复：** 可恢复上一次成功发布的版本，使用保存的内容与素材，不重新生成视频或扣额度。当前编辑草稿另行保留，不回滚账户权限、额度和询盘。
- **下线：** 网址显示暂不可用并停止接收新询盘，保留项目资料，之后可以再次发布；首版没有永久删除整个项目的功能。
- **询盘：** 保存到项目的询盘列表，同时发送完整内容到客户配置的联系邮箱，包括买家联系方式、来源网站、相关产品和留言。发送失败保留记录并显示邮件状态。
- **邮件身份：** 用平台验证过的发信地址发送，回复地址使用买家填写并校验的邮箱。重复提交与重试不能重复创建记录或无限发送。

## 6. 两个项目怎样分工（建议实现方式）

| 负责方 | 工作范围 |
| --- | --- |
| 当前 Product Radar 任务 | 产品勾选后的建站入口、内部建站页面、账号与工作区授权衔接、产品选择与快照输出接口、来源更新接口、集成后的回归验证。 |
| 现有 Web Radar 任务 | 独立登录与完整表单、同一套嵌入式建站流程、项目存储、3 套模板、脚本/分镜/视频、额度与任务队列、预览编辑、发布恢复下线、询盘与管理功能。 |
| 当前任务负责联合验收 | 检查跨站免重复登录、两端同一草稿、权限隔离、原 Product Radar 功能和真实完整建站链路。 |

Web Radar 已由现有任务 **“初始化 Git 仓库”** 使用 **GPT-6 Astra、极高（xhigh）** 实施，工作分支为 `codex/web-radar-v1`。首版本地实施与验收记录见 `docs/web-radar-v1-acceptance.md`；没有另建任务或重复初始化仓库。

建议让 Web Radar 提供一套独立页面和受控嵌入页面，Product Radar 的专用建站页面承载后者。这样完整表单、校验和预览由一处维护。跨站会话采用短时、一次性授权交换；消息检查来源，不把长期登录凭据放进网址，也不依赖浏览器允许第三方 Cookie。

账号授权与产品导入仍通过 Product Radar 的授权接口衔接。Web Radar 自己调用 AI、保存项目并执行发布，不把媒体生成负载转交 Product Radar 服务器。

### 两边共用的接口边界（建议）

| 接口能力与归属 | 输入与输出约定 |
| --- | --- |
| Product Radar：身份与权限核对 | 接收经过验证的会话，返回稳定用户 ID、工作区 ID、角色和可用范围。客户端填写的用户 ID 或公司名不能替代鉴权。 |
| Product Radar：进入建站 | 接收所选产品 ID 和重复请求标识；逐项验证产品访问权，签发绑定用户、工作区、目标来源和用途的短时一次性凭证。Web Radar 服务端交换后打开或创建确定的草稿，重复点击不重复建项目。 |
| Product Radar：产品列表与快照 | 按当前用户权限返回可用产品；所选快照包含来源 ID、版本指纹、名称、已知描述/规格、设计条件与图片引用。图片通过有范围限制的下载方式复制到 Web Radar；不转交云存储主密钥。 |
| Web Radar：项目与草稿 | 使用稳定项目 ID，保存创建者、工作区和草稿版本号。保存时校验预期版本，两个入口同时编辑时提示冲突，不静默覆盖对方修改。 |
| Web Radar：生成任务 | 请求绑定项目、发起者、当前脚本/分镜版本和重复请求标识；返回任务 ID、状态、结果或可处理的失败原因。额度归属从服务端会话确定，完成回调不重新选择扣费账号。 |
| Web Radar：发布与恢复 | 从确认的草稿版本创建不可变发布记录，关联素材和既有 Cloudflare 项目；发布状态与草稿状态分开，恢复不回滚业务数据库。 |
| Web Radar：公开询盘 | 接收网站标识、买家资料、产品标识和留言；服务端核对网站是否已发布，并从可信配置决定收件邮箱，不接受访客随意指定收件人。保存和邮件投递分开记状态。 |

来源更新复用产品快照接口，先比较差异，再由客户选择应用；未获得权限的来源不能通过管理员查看网站的权限间接读取。接口请求和日志只记录必要标识与状态，密钥和长期会话凭据不进入日志。

## 7. 初期 Cloudflare 架构与迁移（建议）

| 部分 | 建议实现 |
| --- | --- |
| 建站前端与接口 | React、TypeScript、Vite，Hono API 运行在独立 Cloudflare Worker；沿用 Product Radar 已有语言与框架经验。 |
| 项目数据 | 独立 D1 数据库，保存项目、草稿、发布版本、权限映射、额度账本、任务状态和询盘。 |
| 图片视频 | 独立 R2 存储；草稿素材私有，给视频提供商读取的素材使用限定范围、有效期足够的临时地址。发布素材只暴露已批准版本。 |
| 后台任务 | SQLite Durable Objects 配合 Alarms 调度保存过的任务，持有 Agnes 唯一活动任务，定时查询进度；图片、邮件与发布也有持久任务状态和有界重试。 |
| 模板与公开网站 | 可信模板预先编译，按项目数据生成静态页面，通过 Pages API 发布到默认地址；每站固定账号/项目/网址关联。 |
| 预览 | 由鉴权接口提供草稿预览，不直接开放未经保护的 Pages 预览地址。 |

每个模板和客户网站不需要常驻一个独立应用进程。页面和模板素材复用静态分发；脚本、图片、视频由外部模型服务生成。发布任务只填充可信模板并上传产物，不为每个客户启动一次完整前端工具链，也不执行客户提供的代码。

关键约束：额度与任务预留要原子处理；提交上游结果不确定时，保留待核对状态，禁止盲目重发。文件流式处理，避免把大批视频同时放进内存。网站下线与访问控制须覆盖平台管理的部署别名；不能仅替换首页却留下可继续收询盘的旧入口。

后续客户提供独立服务器时，将 API 与任务处理迁移过去；提前保留项目、账号映射、素材、询盘、额度、发布关联和在途任务的导出恢复办法。客户网站继续按已确认方式放在 Cloudflare。迁移需要真实目标服务器验证，不承诺只复制目录就完成。

### 费用与容量说明

以下是 2026-09-12 查阅的官方公开额度，不代表你的账号已开通或有全部剩余额度，也不是已批准购买：

- Workers Free 每日 10 万请求，每次 10ms CPU；Paid 基础费用目前最低每月 5 美元，另按超额用量计费。模板填充和发布的 CPU 是否适配 Free，需要用实际产物验证。[Workers 计费说明](https://developers.cloudflare.com/workers/platform/pricing/)
- SQLite Durable Objects 在 Free 与 Paid 都可用；其请求、活动时间和存储另有额度。[Durable Objects 计费说明](https://developers.cloudflare.com/durable-objects/platform/pricing/) Alarms 能在没有浏览器持续连接时唤醒任务，但会至少执行一次，业务必须防止重复副作用。[Alarms 文档](https://developers.cloudflare.com/durable-objects/api/alarms/)
- D1 Free 包含每日 500 万行读取、10 万行写入与合计 5GB 存储。[D1 计费说明](https://developers.cloudflare.com/d1/platform/pricing/)
- R2 Standard 免费部分为每月 10GB-month 存储及一定操作次数，超出部分单独计费。示例：50 个站每站累计保存 80MB 素材约为 4GB，反复生成和历史版本会继续增加，这只是容量假设。[R2 计费说明](https://developers.cloudflare.com/r2/pricing/)
- Pages 当前每账号最多 100 个项目；多把同账号 token 不增加这个上限。发布时检查账号实际剩余容量与单文件限制，超限素材不能静默丢弃。[Pages 限制](https://developers.cloudflare.com/pages/platform/limits/)

20–50 人在线作为验收目标，分别验证填表/预览/保存和任务排队，不等同于 50 条视频同时生成。上线前按实际账号和测得请求、CPU、素材量出一份费用估算；此前讨论的每月 20 美元预算没有被批准，本方案也不默认开通付费套餐。

## 8. 接通真实服务所需配置

这些是服务配置依赖，可以在开发过程中准备；没有配置时应明确标为未接通，不伪装生成或发信成功。密钥通过本地配置或服务端 Secret 安全写入，不贴在聊天或前端。

| 配置 | 当前状态与处理 |
| --- | --- |
| Image 2.5 新 key | 已确认由你提供，尚未验证。模型按当前仓库的 gpt-image-2.5-sunburst 对接，真实账号需有权限；不复制旧 key 或回退 key。 |
| Agnes key 与模型权限 | 已确认使用 Agnes，尚未验证你的账号、当前免费资格、额度和并发。按一条完整视频接入，不自动切换收费模型。 |
| 文字模型 | 建议脚本、网站文案和翻译共用一套独立配置的 OpenAI 兼容接口；现有 Product Radar 代码使用 gpt-5.5，可作为初始兼容配置。实际服务地址、模型和专用 key 需要配置与验证，不假定图片 key 自动拥有文字权限。 |
| Cloudflare token | 你将提供数个；接入时核对对应账户、权限与资源归属，选定 Web Radar 后台和素材的独立资源，核算与其他业务共用账户额度的影响。 |
| 账号衔接 | 接入现有 Supabase 身份与 Product Radar 工作区授权；核实回调地址、允许的跨站来源及服务间凭据，不替换现有登录。 |
| 询盘邮件 | 建议首版使用 Resend 的 HTTP 发信接口；需要平台发信域名验证和专用 key。客户的联系邮箱是收件人，平台发信域名由你控制。 |
| 真实验收材料 | 一组允许用于测试的产品和公司资料、明确的测试收件邮箱，以及允许公开发布的样例内容。 |

文字模型接口依据当前仓库的 `src/worker/product-creations.ts`、`src/worker/product-creation-ai.ts` 核对；这不是对已配置密钥或实时模型可用性的确认。邮件建议依据 [Resend 官方接口](https://resend.com/docs/api-reference/emails/send-email)，发件域名与收件地址分开设置。发信失败和垃圾提交处理需在上线前验收。

## 9. 先做什么、怎样算完成（建议交付顺序）

1. **先固定两个项目的接口与数据归属。** 当前任务负责 Product Radar 的授权、产品快照契约；Web Radar 任务负责建站 API 与共享流程。接口契约在双方实现前对齐。
2. **跑通一套模板的完整链路。** 同账号两入口 → 同一草稿 → 脚本确认 → 分镜确认 → 视频 → 预览 → 发布 → 询盘。这是实施顺序，首版最终仍交付 3 套模板。
3. **补齐另外两套模板和已确认管理能力。** 包括双语、单图重做、额度、来源刷新、版本恢复和下线。
4. **联合验证后接入真实配置。** 先用明确标识的测试数据验证本地流程，再对已授权的真实账号、素材、邮箱与 Cloudflare 资源验证实际效果。真实付费调用、发信和公开发布的对象与范围要明确。
