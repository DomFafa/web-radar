# EDM 邮件与站内信集成

## 入口与范围

工作台左侧增加「EDM 邮件」和「站内信」，沿用 Web Radar 登录、会话和工作空间。

- EDM：发送中心、联系人及分组、CSV/Excel 导入与导入报告、邮件模板和富文本编辑器、AI 文案、营销活动、发送进度及统计、服务商配置、发信域名。
- 站内信：向目标网站的联系表单留言，创建/编辑任务、批量目标、逐站进度、暂停、重试、结果导出。不是平台用户之间的聊天。
- 原 OutlookMatrix/edm 保持独立；不自动复制其联系人、历史任务或密钥。
- EDM 服务商配置独立于网站询盘使用的 Resend 设置。请在 EDM 的「服务商配置」中添加所需发信和 AI 服务商；域名验证功能取决于对应服务商支持。

## 数据与权限

迁移 `0007_outreach.sql` 创建 `edm_` 前缀表，与现有建站数据分离。兼容源模块的 `edm_users` 仅作为工作空间数据归属映射，不是第二套账号系统。

- 同一工作空间共享联系人、模板、活动和站内信任务；跨工作空间请求返回 404。
- 工作空间管理员及超级管理员可管理服务商；普通成员可操作内容和任务。
- 服务器以现有身份认证和 CSRF 校验作为唯一入口，上传和导出也使用现有会话。
- 服务商 API key 与配置中的凭据使用 AES-GCM 加密，绑定具体记录；列表只返回掩码。加密密钥来自现有 `ASSET_SIGNING_KEY`，更换该密钥前需迁移凭据。
- 邮件预览使用无脚本权限的 sandbox iframe。公共退订和邮件跟踪链接使用签名令牌。
- 网络请求检查公开地址和重定向；站内信浏览器请求同样拒绝内网目标。验证码不自动绕过，保留人工处理结果。

## Cloudflare 部署

在已有 D1、R2、Durable Object 配置上新增：

| 绑定 | 资源 |
| --- | --- |
| EDM_EMAIL_QUEUE | web-radar-edm-email |
| 邮件恢复队列 | web-radar-edm-email-dlq |
| EDM_SITE_QUEUE | web-radar-edm-sites |
| BROWSER | Cloudflare Browser Rendering |

先创建队列并应用 D1 迁移，再部署包含生产者/消费者的 Worker。站内信消费者并发为 1，邮件并发为 2。生产缺少必要队列或浏览器绑定时，启动接口返回明确错误。

`APP_ORIGIN` 用于图片、退订和跟踪链接，必须是可从公网访问的 Web Radar 地址。`ASSET_SIGNING_KEY` 必须保留现值。生产使用现有 Web Radar 域名和私有 R2 存储。

## 执行与重试

邮件以收件人为单位记录发送尝试，并将未知结果交给恢复逻辑核实，避免盲目重发；消费者按活动分组，避免不同工作空间混用服务商。

站内信重复启动被拒绝。重置必须先暂停并等待当前网站处理结束。提交后进程中断而结果未知的目标标为 `submission_uncertain`，不自动重发；确认实际结果后才能通过单任务重置重新处理。

测试环境允许编辑草稿和查看功能，但启动实际发信/外站提交返回 503，避免误发。

## 验证

- `npm run check`：类型检查、项目回归测试、前端构建。
- `npx vitest run tests/outreach`：导入幂等性、导入报告、批量操作和数据隔离、服务商密钥加密、邮件发送尝试幂等性。
- `node scripts/verify_outreach.mjs`：临时本地 D1、认证导航、联系人/模板/活动/站内信草稿、权限隔离、密钥脱敏、富文本编辑器、刷新恢复、移动端布局。可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定 Chrome。

验证不会发送真实邮件，也不会向外部网站提交表单。真实服务商投递率和目标网站表单兼容性需使用运营方配置与授权目标进行验收。
