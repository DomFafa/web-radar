# 需求沟通与静态建站流程验收

日期：2026-09-13。代码位于现有 `codex/web-radar-v1` 工作分支，本次未提交、推送或部署生产。

## 已实现的流程

保留工作台布局与原有公司、产品、项目名称及社交链接编辑功能。五步导航为：资料与产品 → 需求沟通 → 网站方案 → 页面设计稿 → 预览与发布。

需求沟通使用原始产品图片、Logo、已填资料及回答历史。一次只显示一道题，四个模型选项，第五项固定“都不是，我要自定义”；选中第五项后才显示文字输入框。资料足够时提前整理方案。模型最多收集十次回答，未知事实明确省略。客户确认视觉方向、保留/避免条件、文案和页面清单后才能生成首页。

页面清单包含五个基础类型及最多三个有业务依据的扩展展示页。首页确认后，其余图片同时参考首页、原产品图和已确认资料。所有计划页必须齐全并确认，才能进入 screenshot-to-code。详情模板按实际产品分别展开，保留原图、询盘与语言导航。

服务端维护问题 ID、答案、方案和确认状态。重复提交复用任务；资料改动撤销相关确认；旧任务不能覆盖新资料。方案修改触发追问时，原方案与修改要求保存在 revisionContext，回答后继续使用，完整新方案返回才清除。文案或译文被改动也会撤销方案确认。已发布快照及旧静态产物保留原行为。

## 复刻与运行边界

Python 服务接受精确的计划页图集。所有已确认页面段落均使用受限绑定填入，逐段验证只出现一次且保持顺序；在批准方案时即拒绝各语言段落数量不一致。基础页保留既有产品、标题及联系表单绑定，详情页段落使用可复用的通用措辞。未修改供应库源码。

已确认本地服务无排队或执行中任务后，重启 `127.0.0.1:7002` 加载新代码；带鉴权读取已有任务返回 HTTP 200。服务没有独立 health 路由。`SITE_BUILDER_KEY` 已配置，`SITE_BUILDER_URL` 仍为空；生产 Worker 尚无可访问的 Python 构建地址。

本次没有重新生成整套真实图片或复刻产物，也没有部署线上。此前真实复刻的视觉问题仍以 `docs/static-site-acceptance.md` 的记录为准；本次流程与约束验证不能替代后续真实新方案的生图、复刻和视觉验收。
